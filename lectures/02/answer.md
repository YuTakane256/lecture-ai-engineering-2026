# 第2回：基盤モデルの仕組み

## 演習

### 使用モデル・設定

- 基盤モデル：`Qwen/Qwen3.5-0.8B`（revision: `2fc06364715b967f1860aea9cf38778875588b17`）
- 方式：LoRA（基盤モデルの量子化なし）
- `lora_r=16`、`lora_alpha=32`、`lr=0.0002`、`num_train_epochs=20`、`warmup_steps=6`、`max_seq_len=512`、`seed=42`、`max_new_tokens=96`、`do_sample=False`
- 学習は自分で実行した（`executed_training_myself=true`）。

### 学習前後の評価（21問）

| 指標 | 学習前 | 学習後（20エポック） |
|---|---:|---:|
| 形式遵守率 `format_rate` | 2/21 = 9.52% | 21/21 = 100.00% |
| 内容正解率 `content_rate` | 0/21 = 0.00% | 19/21 = 90.48% |
| 形式・内容とも正しい割合 | 0/21 = 0.00% | 19/21 = 90.48% |

- `regressed=[]`。ただし学習前に形式・内容とも正解の質問がなかったため、これだけで退行がないと一般化できない。
- 学習後の失敗例：「成績はいつ出ますか」への根拠のない日付の断定、「オフィスアワーは事前予約が必要ですか」に対して予約要否を確認せず、時間だけを回答したこと。いずれも未知の情報に関連する回答の誤り。
- 用語集ではなく演習用FAQにない知識を尋ねた4問の学習後分類：最終課題の締切=`asserted`（誤った断定）、担当教員=`needs_review`、次回の講義テーマ=`needs_review`、対照問題の課題提出期限=`asserted`（FAQに根拠のある回答）。なお最終課題の締切への回答では、別のFAQ項目にある提出期限を転用してしまった。
- LoRAによりJSON形式とFAQに沿う回答は大幅に改善したが、資料に根拠がない質問を確実に見分ける能力までは保証されなかった。

## 宿題

### 取り組んだレベル：発展

講座の用語集から`uv run python scripts/make_sft_dataset.py > glossary_sft.jsonl`で、`messages`形式の116件のQ&Aを生成した。異なる正解文ごとにまとめ、ランダムシード42で46用語／92件を学習用、12用語／24件をholdoutとした。用語単位で同じ説明文が学習側とholdout側に重複しないようにした。

### 学習・評価の条件

- 基盤モデル：`Qwen/Qwen3.5-0.8B`。LoRA rank 16、alpha 32、学習率 0.0002、2エポック、量子化なし、seed 42。
- 学習時は「AI技術の用語を日本語で簡潔・正確に説明し、不明な用語を捏造しない」というsystem指示を追加した。評価時も同じ指示を用いた。
- 評価問題：学習した用語の元の質問6問、同じ用語の言い換え6問、学習していない用語6問、架空の用語3問、合計21問。正解・参照文は用語集に基づいて用意した。
- 検索比較：①全58用語を検索できる辞書、②学習対象の46用語だけを検索できる辞書。用語名の完全一致（質問内の「」など）を利用する簡易検索であり、意味検索やLLMを組み合わせたRAGではない。

### 検索方式の結果

| 質問の種類 | 全用語集検索（58用語） | 学習対象用語のみ検索（46用語） |
|---|---:|---:|
| 学習済み用語・元の質問 | 6/6 | 6/6 |
| 学習済み用語・言い換え | 6/6 | 6/6 |
| 学習していない用語 | 6/6 | 0/6 |
| 架空の用語（正しく非該当と答える） | 3/3 | 3/3 |
| **合計** | **21/21（100%）** | **15/21（71.4%）** |

検索の高得点は、すべての質問に用語名が明示され、検索が正解文を直接取得できる条件による。全用語集検索と学習対象のみの検索では利用可能な知識量が異なる点にも注意する。

### LoRA学習前後の評価結果（21問）

- 学習環境：ColabのGPU（T4）、使用モデル `Qwen/Qwen3.5-0.8B`（指定revision）。LoRA rank 16、alpha 32、lr 0.0002、2エポック、warmup 3、最大系列長512、最大生成トークン256、生成はサンプリングなし。
- 実測学習時間 **82.34秒**、学習ステップ **24**、最終記録Loss **1.2768**。学習前の全21問生成に239.80秒、学習後には97.31秒かかった（生成時間は条件・回答長の影響を受ける）。
- 採点方法：`comparison_review.csv`の各回答を参照文と照合し、**中心的事実を概ね正しく説明し、重大な捏造がない**ものを正解（1）、そうでないものを不正解（0）とした。逐語一致ではなく目視による判定。学習率の説明など一部境界的な回答を含むため、数値は厳密な客観評価ではない。

| 評価質問の種類 | 学習前 | LoRA学習後 |
|---|---:|---:|
| 学習済み用語・元の質問（6問） | 2/6 | 2/6 |
| 学習済み用語・言い換え（6問） | 2/6 | 2/6 |
| 学習していない用語（6問） | 2/6 | 2/6 |
| 架空用語への適切な非断定（3問） | 0/3 | 0/3 |
| **合計（21問）** | **6/21（28.6%）** | **6/21（28.6%）** |

正解となった質問の内訳も変化した。学習前は「学習率」2問・「ツール」2問・「Hugging Face Hub」・「GitHub Copilot」が正解、学習後は「学習率」2問・「ツール」2問・「Hugging Face Hub」・「環境変数」が正解と判定した。**今回の設定では総合正解率の改善は観察できなかった。**

代表的な失敗例は以下のとおり。

- 学習済み用語「エポック」：学習後も「最初の100回の学習回数」など、用語集にない数値を含めて誤説明した。
- 学習済み用語「fetchサーバー」：学習後は「モデルの出力を外部へ送信するサーバー」と回答し、URLの取得・Markdown化という機能を再現できなかった。
- 学習対象外「GitHub Copilot」：学習前はコード生成・修正支援の概要を説明したが、学習後はGitHubアカウントのパスワード共有ツールだと誤説明した。追加学習後の悪化の例である。
- 架空用語「ゼフィリオン・プロトコル」：学習後にGoogleが公開した技術のルールと根拠なく断定した。残り2件の架空用語も実在するように説明し、`unknown`は0/3だった。

なお、生成文の短文化（学習前の239.80秒→学習後の97.31秒）は確認できたが、GPUの実行時間は文章長やランタイム状態の影響も受けるため、推論自体が高速化した証拠とはできない。最終Lossは学習データに対する指標であり、評価問題での正解率を保証しない。

### 考察

今回の2エポック・92件のLoRA学習では、**用語集の知識を安定して再現する水準には到達しなかった**。少数データ・短い学習・モデル容量・指示と学習形式・生成条件などが影響した可能性はあるが、この1回の実験だけで原因を特定できない。特に「学習済み用語」でも誤答が多く、学習データに含めた事実だからといって確実に記憶されるわけではないと分かった。過学習や学習不足を断定するには、学習量を変えた追加実験や検証Lossが必要。

検索方式は、全用語集で21/21、学習対象46用語のみでも15/21と、今回のLoRAモデルより高かった。ただし、**検索は用語の綴りが質問に明示され、正解文が辞書にそのまま格納されている有利な条件**である。用語名を使わない質問、複数の概念を組み合わせる質問、曖昧な言い換え等を試せば、この単純検索にも限界が現れると予想される。また、全58用語検索と92件（46用語）で学習したLoRAでは参照できる情報量が異なる。

**結論**：変わりやすい事実や正確な定義の参照には、外部用語集の検索が適している。LoRAは、回答形式・スタイル・特定タスクへの適応には有用な可能性があるが、知識を覚えさせる目的では学習回数を増やせば必ず正しくなるわけではなく、未知の質問に対する捏造も残る。実用化するなら検索とモデルの役割分担、未登録用語に対する回答保留の設計、独立した評価セットでの検証が必要だと考えた。
