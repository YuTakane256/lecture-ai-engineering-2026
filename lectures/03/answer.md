GitHub CodespacesにPiをインストールし、Gemini 3.5 Flash-Liteを使用して実行した。リポジトリの構成を調査し、app/agent.py と app/tools.py の役割、およびモデル設定・ツール登録・実行ループの実装箇所を説明するよう指示した。ファイルの編集や削除は行わないよう指定した。

Piはbashでディレクトリ構造を調査し、readで4回に分けてapp/agent.py、app/tools.py、app/config.pyを読み取った。合計5回のツール呼び出しを経て、build_model()によるモデル設定、agent.tool_plain()によるツール登録、target.run_sync()を起点としたPydantic AI内部の実行ループを正しく説明できた。実行ログではeditやwriteの呼び出しはなかった。

システムプロンプトの比較

Piのシステムプロンプトには、コーディング支援という役割に加え、read・bash・edit・writeというツールの用途や、ファイル調査・編集時のルールが記載されている。また、作業ディレクトリやドキュメントの参照先なども含まれていた。
一方、自作したPydantic AIエージェントのINSTRUCTIONSは、AIエンジニアリング講座の学習支援に特化している。用語集の検索、講義要点の取得、不明な情報の扱い、回答形式などを規定している。
両者は目的とツールの種類が異なるが、LLMに役割と行動方針を指示し、必要なツールを呼び出して結果を回答に反映する構造は共通している。また、実行ループはプロンプトではなく、PiやPydantic AIのハーネス側が管理している。

工夫・難しかった点と考察
モデルの混雑による503エラーや、APIの利用制限・モデル提供状況による404・429エラーが発生し、モデルの選択と切り替えに苦労した。
今回、Piのシステムプロンプトだけでなく、実際のツール実行履歴と自作エージェントのコードを対応させて比較した。これにより、コーディングエージェントの機能はLLMだけでなく、ツールの設計、実行ループ、コンテキスト管理などのハーネスによって支えられていることを具体的に理解できた。

また、読み取り専用の指示に従って実際にはファイル変更が行われなかったものの、Piには編集ツール自体が登録されているため、厳密に変更を禁止するにはプロンプトだけでなくツール権限などによる制御も必要だと考えた。
今後は、長時間の開発作業におけるコンテキスト管理、ツールの選択、APIコストの最適化など、ハーネスの設計についてさらに理解を深めたい。
